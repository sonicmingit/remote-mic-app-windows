# Windows 剪贴板听写验收

## 自动化

`pnpm test`、`pnpm build`。新增宿主 capability 需在具备完整工具链时执行
`scripts/ci-preflight.ps1` 与 `scripts/build-local-test-package.ps1`。

## 本地安装与真实豆包

安装前正常退出正在连接的 SayAll，不强杀。验证升级保留设置、安装版启动，豆包入口可见。
RC001 和 RC003 各自记录 passed / failed / deferred，不互相替代：

1. 在豆包面板打开听写窗口。初始为空，焦点在输入框；选中豆包为当前 Windows 输入法。
2. 冷态/真实闲置后首次按住语音键说话，松开后等识别完成。将结果粘贴到独立记事本，
   与窗口内容逐字比对；不能只看“已复制”状态或 Clipboard API 返回值。
3. 连续说两段，包含标点、换行和中英文；粘贴结果包含窗口全部文字，不只包含最后一段。
   较长一段确认输入中的临时组合文字不触发复制，最终整理结果仍自动更新剪贴板。
4. 在不能直接接收豆包文字的目标软件重复步骤 1–3，通过手动粘贴确认可接收结果。
5. 点“清空内容”后在记事本粘贴，剪贴板仍是上一段；再说新内容只包含新文字。
6. 模拟剪贴板被占用/拒绝写入：窗口保留文字并提示失败，恢复后“复制全部”可重试。
7. 点击入口两次、最小化后再打开：只有一个窗口，原文字仍在，输入焦点可用。
   关闭后重开：文字为空，剪贴板保留。关闭/切走时没有排队复制覆盖用户后来复制的内容。
8. 断连、取消、睡眠恢复、快速按下/释放与退出：原语音生命周期与基础输入不回归，
   回来后新会话可用。记录冷态和热态结果，不能只测热态。
9. 简体中文/英文、浅色/深色与小窗口宽度核对；普通直接输入路径仍可用。
10. 诊断只包含 `clipboard_dictation_open` / `clipboard_dictation_copy` 的阶段、结果、
    短操作标记和耗时；无听写正文、设备身份或个人路径。确认没有新建文字历史文件。

受控自动化已覆盖慢剪贴板写入、迟到回调和宿主创建超时；真实剪贴板被占用场景应另行记录。
原生 Clipboard API 已提交的写入没有取消接口，不能声称关闭窗口能撤销已提交的系统操作。
